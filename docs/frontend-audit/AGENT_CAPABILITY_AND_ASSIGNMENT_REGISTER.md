## 1. Executive Summary & Purpose

This register establishes the organizational and capability baseline for the comprehensive forensic audit and engineering transformation of the **GREEN AI** full-stack scientific software product. 

GREEN AI is an enterprise-grade measurement, benchmarking, analytics, and optimization platform for Machine Learning training and inference energy consumption and operational carbon emissions. It bridges software-level telemetry (Intel/AMD RAPL, NVIDIA NVML) with optional hardware-instrumented physical current sensing (ESP32-S3 + INA219).

To ensure rigor, zero superficiality, and total technical fidelity, 26 distinct enterprise departments and specialized agents have been mobilized. Each department operates with a defined mandate, domain-specific evaluation heuristics, and direct ownership of specific artifacts across the 11 audit phases.

## 3. Operational Protocols & Review Constraints

1. **Strict Evidence-Driven Assessment**: No claims of high performance or cleanliness without tangible proof (build logs, bundle sizes, WCAG contrast ratios, code line numbers).
2. **Preservation Invariant**: Backend FastAPI services, SQLite database schema, RAPL and carbon intensity mathematical calculations must remain untouched unless a documented vulnerability or blocker requires remediation.
3. **Intellectual Honesty on Hardware**: GREEN AI's hardware integration is software-modeled/simulated in the current staging environment. The UI must explicitly state data provenance ("Software RAPL Model" vs "Simulated Hardware Telemetry" vs "Physical Sensor Stream") to eliminate fraudulent presentation.
4. **Zero Superficiality**: Findings must not stop at "the button looks old" — each issue must be traced to root causes in component design, typography hierarchy, token abstraction, or DOM accessibility tree.
